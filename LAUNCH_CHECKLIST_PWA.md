# KinCircle PWA Launch Checklist

This checklist prepares our PWA-first MVP and native Driver Safety shell for a public launch. Work top-to-bottom and check items off as you go.

---

## 1) Technical Pre-Launch (Final Checks)

### A. Supabase (Production Setup & Migration)

- [ ] Create/confirm Production Supabase project (separate from staging)
- [ ] Set Project Settings → General → Site URL to `https://app.kincircle.com`
- [ ] Auth → URL Configuration:
  - [ ] Add Redirect URLs: `https://app.kincircle.com`, `https://app.kincircle.com/dashboard`
  - [ ] Allow localhost redirect for emergency testing: `http://localhost:3000`
- [ ] Auth → Email Templates: brand the magic-link email (logo, colors, support link)
- [ ] Database → SQL Editor: apply our production schema
  - [ ] Paste and run `pwa/infra/supabase/schema.sql`
  - [ ] Verify tables created: `profiles`, `families`, `family_members`, `invites`
  - [ ] Verify RLS is enabled on all tables and policies exist (sender + recipient rules for `invites`)
- [ ] Database → Policies: spot-check RLS
  - [ ] Confirm recipients can read/delete their invites
  - [ ] Confirm only owners can insert `families` and add `family_members`
- [ ] API Keys:
  - [ ] Copy Production `anon` key (client-side)
  - [ ] Store `service_role` key only in server-side environments (never commit)
- [ ] Storage (if used later): create buckets with public/private defaults and rules
- [ ] Turn on Point-in-Time Recovery (if on Pro/Team plan) for rollback safety
- [ ] Configure Rate Limits / Abuse controls appropriate for launch

### B. Environment & Secrets

- [ ] PWA `.env.production` (or hosting provider env vars):
  - [ ] `NEXT_PUBLIC_SUPABASE_URL`
  - [ ] `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- [ ] Supabase project `JWT secret` autogenerated (no change unless migrating)
- [ ] Never expose `service_role` on client; only use server-side where absolutely needed

### C. Domain (PWA at app.kincircle.com)

- [ ] Choose host (Vercel/Netlify/Fly/Cloudflare Pages). Example (Vercel):
  - [ ] Connect GitHub repo (PWA at `pwa/`)
  - [ ] Set project root: `pwa`
  - [ ] Build command auto-detected by host
  - [ ] Set env vars in project settings (from above)
- [ ] DNS:
  - [ ] Create CNAME for `app.kincircle.com` to hosting provider target
  - [ ] (Optional) Root domain `kincircle.com` → marketing site; redirect `/` to PWA if desired
- [ ] SSL auto-provisioned by host; confirm certificate is active
- [ ] Add `app.kincircle.com` to Supabase allowed redirect URLs (Auth Settings)

### D. PWA Fit & Polish

- [ ] Manifest: `pwa/public/manifest.webmanifest` – name, icons (512, 192), theme/background
- [ ] Service Worker: ensure caching strategy is safe and deploy-ready (`sw.js`)
- [ ] iOS meta tags for standalone mode and status bar styles
- [ ] Basic SEO: title/description, OpenGraph/Twitter image, sitemap/robots

### E. Native Shells (Flutter Driver Safety app)

- [ ] Versioning: bump `pubspec.yaml` version for release
- [ ] Assets: confirm `assets/models/driver_safety.tflite` is included and loads in release
- [ ] Permissions & Declarations:
  - [ ] iOS: confirm no missing usage descriptions (accelerometer/gyro typically don’t need extra strings)
  - [ ] Android: `minSdkVersion`/`targetSdkVersion` aligned with Play policies
- [ ] Release builds:
  - [ ] Android keystore: generate and configure `key.properties`; produce `appbundle (.aab)`
  - [ ] iOS: create App ID, provisioning profile, distribution cert; archive and upload via Xcode
- [ ] Store assets:
  - [ ] App name, short description, full description
  - [ ] Screenshots (phone), feature graphic (Play), app icon, promotional text
  - [ ] Privacy Policy URL, Terms of Service URL
  - [ ] Content rating questionnaires (both stores)
  - [ ] Export compliance (Apple), Data Safety (Google)
- [ ] Internal/TestFlight testing: install on real devices, verify Driving Mode and Safety Report
- [ ] Final release submission in App Store Connect and Google Play Console

### F. Final QA (Critical E2E Scenarios)

PWA (Production):

- [ ] Sign up via magic link → redirected to `/dashboard`
- [ ] Create family → appears in list; owner is admin
- [ ] Send invite → recipient receives invite in real-time
- [ ] Accept invite → invite disappears; family list updates live; RLS allows membership read
- [ ] Decline invite → invite removed
- [ ] Auth guard: direct access to `/dashboard` while signed-out redirects to `/`
- [ ] RLS spot-check via API: recipient cannot access other users’ invites; members only see their families

Native Shell:

- [ ] Driving Mode: Start → sensors active; End → sensors stopped
- [ ] Incidents get persisted locally (trigger by moving device or use test harness)
- [ ] Safety Report lists incidents with type and timestamp
- [ ] App handles missing model or interpreter gracefully (no crash)
- [ ] Battery usage acceptable for a short drive test

## 3) Post-Launch Monitoring

### A. Analytics (Privacy-first)

- [ ] Choose analytics: Plausible/PostHog (self-hostable) or GA4
- [ ] Track key events in the PWA:
  - [ ] `signup_completed`
  - [ ] `family_created`
  - [ ] `invite_sent`
  - [ ] `invite_accepted`
  - [ ] `invite_declined`
- [ ] Create a simple dashboard for daily/weekly active, conversion from invite → accept, and family growth
- [ ] Respect privacy: anonymize IPs (if possible), avoid PII in events

### B. Support Readiness

- [ ] Set up support email (<support@kincircle.com>) and auto-acknowledgement
- [ ] Create a lightweight help center (Notion/Docs) linked from the app
- [ ] Add in-app “Report an issue / Send feedback” link
- [ ] Define SLAs for responses (e.g., <24h weekdays)
- [ ] Optional: add a status page for incident communication

## Final Go/No-Go

- [ ] All QA pass in production
- [ ] Stores approved and set to release timing
- [ ] Domain + SSL configured
- [ ] Analytics & support ready
- [ ] Announcements scheduled
